## <font style="color:rgb(23, 23, 23);background-color:rgb(252, 252, 252);">1) 表：public.energy_data</font>
<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">概况（从列清单）：timestamp (timestamptz), building_id (text), electricity_kwh (real), water_m3 (real), hac_energy (real), sim_supply_temp_c (real), sim_return_temp_c (real), air_temp_c (real), dew_temp_c (real), humidity_rh_pct (real), anomaly_status (text)。表无主键，行数较多 (~26k)。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">逐列解释</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">timestamp (timestamp with time zone)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：观测数据或度量值的时间戳（通常为设备上报时间或聚合后的时间点）。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计要点：使用带时区时间戳（timestamptz）有助于跨时区统一处理；通常以 UTC 存储。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">building_id (text)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：关联到某个建筑实体（public.buildings.building_id）。指示该行数据属于哪个建筑。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计要点：应与 buildings 表建立外键关系以保证引用完整性；建议将类型与 buildings.building_id 保持一致（prefer text 或 uuid）。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">electricity_kwh (real)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：在该时间点或时间段内测得的电量消耗（单位千瓦时）。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计要点：real 为 32-bit 浮点，适合存储采样值，但对分析/精度要求高时建议使用 double precision。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">water_m3 (real)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：水用量（立方米）。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">hac_energy (real)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：供暖/空调等 HVAC 系统消耗的能量（单位需在文档中明确，可能为 kWh）。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">sim_supply_temp_c / sim_return_temp_c (real)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：仿真或模型计算的供/回水温度（摄氏度），用于与实际测量对比或计算效率。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">air_temp_c / dew_temp_c (real)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：环境空气温度与露点温度（摄氏）。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">humidity_rh_pct (real)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：相对湿度百分比。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">anomaly_status (text)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：与该时间点数据有关的异常状态标识（例如 'ok', 'anomaly_detected', 'sensor_offline' 等）。若需要结构化信息，建议改为枚举或 jsonb。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">主键与键的含义</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">当前状态：表没有主键（no primary key）。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：数据库不会强制防止重复行，且对某些更新/删除操作不易确定目标行。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">建议主键方案：</font>
        * <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">组合唯一键： (building_id, timestamp) —— 适用于每个建筑在某个时间点只有一条记录（常用于定时上报或按分钟/小时汇总）。</font>
        * <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">或单列 UUID：添加 id uuid DEFAULT gen_random_uuid() 作为主键，便于引用与去重。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">建议索引：</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">建立索引以优化常见查询：CREATE INDEX ON energy_data (building_id, timestamp DESC);</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">若按时间范围聚合，索引 timestamp 单列或联合索引能显著加速查询。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">如果按 anomaly_status 过滤，考虑为 anomaly_status 建立索引或使用部分索引（WHERE anomaly_status IS NOT NULL OR anomaly_status <> 'ok'）。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计模式与使用场景</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">时间序列模型：此表本质上是时间序列数据（meter/传感器/聚合读数）。设计应考虑高写入吞吐与按时间的聚合查询。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">典型操作：按 building_id + 时间范围查询（聚合小时/日）、检测异常、与仿真预期值比对、生成报表。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">可扩展性考虑：若数据量增长很大，考虑使用 TimescaleDB 扩展（hypertable）、或基于时间分区（PARTITION BY RANGE (timestamp)）来提高性能与管理成本。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">一致性/精度考虑</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">数据类型：当前使用 real（float4）。浮点精度有限，若下游分析有严格数值要求，推荐改为 double precision。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">单位与元数据：表设计未明确单位（哪些列是 kWh、℃ 等），应在数据字典/列注释中明确。</font>

## <font style="color:rgb(23, 23, 23);background-color:rgb(252, 252, 252);">2) 表：public.devices</font>
<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">概况：device_id (text, PK), building_id (text), device_type (text)。行数较少（9）。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">逐列解释</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">device_id (text) — 主键</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：设备唯一标识符，例如传感器序列号或网关 ID。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计要点：将其设为主键表明每台设备只应出现一次在 devices 表中。类型为 text，若设备 id 为 UUID 或固定格式，建议使用更精确类型（uuid 或 varchar(n)）。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">building_id (text)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：设备所属的建筑（外键指向 buildings.building_id）。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计要点：应建立外键约束以保证引用的建筑存在；如果设备可能迁移建筑，考虑是否允许 NULL 或记录历史（device_assignments 表）。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">device_type (text)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：设备类别（例如 'electric_meter', 'water_meter', 'hvac_sensor' 等）。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计要点：如果设备类型是有限集合，建议使用 enum 或单独的 device_types 参考表以保证类型一致性，并方便扩展元数据（如采样频率、单位、制造商等）。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">主键、外键与索引含义</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">主键 device_id</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">用途：保证设备唯一；用于与其他表（如 energy_data、anomaly_events 或设备原始数据表）建立关系。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">外键建议</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">device.building_id -> buildings.building_id：保证设备归属建筑的完整性，并能方便查询某建筑下所有设备。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">索引</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">如果频繁按 building_id 查找设备，建议建立索引：CREATE INDEX ON devices (building_id);</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计模式与使用场景</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设备登记/元数据表（Device Registry）：devices 存储设备的静态信息（ID、类型、所属建筑）。动态读数放在 energy_data 或独立的 telemetry 表中。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">典型关系：一个 building 可以有多台 device（1:N），一台 device 属于一个 building（或若允许则为 N:M，需中间表）。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">扩展建议</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">添加更多设备元数据：installation_date, model, manufacturer, status, last_seen_at。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">若设备会迁移或可能同一个设备对多个建筑（临时测量），考虑建立 device_assignments 或 device_history 表来记录变更。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">概况：building_id (text, PK), primary_space_usage (text), sqm (real)。行数少（3）。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">逐列解释</font>

    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：建筑唯一标识（例如楼宇编号、项目代码或 UUID）。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计要点：应与其他表中 building_id 类型一致；若有统一 ID 格式，建议使用 uuid 或固定长度 varchar。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">primary_space_usage (text)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：建筑主要用途（例如 'office', 'residential', 'retail', 'hospital' 等）。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计要点：可用作分类、能源基线设定或策略分组。建议用枚举或参考表以保证一致性。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">sqm (real)</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">含义：建筑或该建筑主体使用面积（平方米）。</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计要点：用于按面积归一化能源强度（如 kWh/m2），建议为 double precision 或 numeric(10,2) 以保留精度。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">主键、外键与索引含义</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">主键 building_id</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">用途：唯一标识建筑，用于能耗数据分组、权限控制（按 building_id 限制用户访问）等。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">作为外键目标</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">energy_data.building_id、devices.building_id、anomaly_events.building_id 等应引用 buildings.building_id，以确保引用完整性。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">索引</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">主键隐式索引已存在；如果按 primary_space_usage 进行大量筛选，可为该列建立索引或使用分类表。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">设计模式与使用场景</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">主实体（Master/Dimension）模式：buildings 表为维度表（在分析查询中用于 join 能耗数据以获取元数据，如面积和用途）。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">典型操作：按建筑聚合能耗、计算强度指标（能源密度）、分组对比（同类用途建筑比对）。</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">devices 与 energy_data</font>
    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">当前模式：energy_data 没有 device_id 字段（仅 building_id）。这表示：</font>

    - <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">建议：若需要按设备分析或追溯故障，添加 device_id 到 energy_data（并建立外键指向 devices.device_id）。</font>

<font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">ER 关键点</font>

+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">若系统要求能按设备溯源或做设备级聚合，应把 telemetry/reading 表与 devices 直接关联。</font>
+ <font style="color:rgb(82, 82, 82);background-color:rgb(252, 252, 252);">如果 energy_data 是已按建筑聚合（例如多设备数据在边缘网关已合并），那当前设计合理，但请在数据字典中明确。</font>
