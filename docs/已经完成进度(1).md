### 前后端对接方式说明（重点）

#### 1. 基础约定

- **后端 Base URL**
  - 开发环境：`http://localhost:8000`
  - 所有接口前缀以 `FastAPI` 实际路由为准，一般习惯是：
    - 聊天流：`/api/chat/...`
    - 数据接口：`/api/data/...`
- **前端技术栈建议**
  - Vue 3 + Vite + Pinia + ECharts（文档中已规划好目录结构）。
  - SSE 客户端封装文件预期在：`frontend/src/api/stream_client.js`。

#### 2. SSE 流式聊天接口（对话 + Thinking + Artifacts）

> 该接口是前端与“多智能体大脑”的主通道，用于驱动「聊天区 + 动态图表 / 卡片」的联动。

- **接口形态（示意）**
  - 方法：`GET` 或 `POST`（视 `routes_chat.py` 实现而定，一般是 `POST /api/chat/stream`）。
  - 返回：`text/event-stream`，标准 SSE。
- **事件流内容（逻辑层面）**
  - 普通文本消息：
    - 用于渲染聊天气泡（用户问话 + AI 回答）。
  - Thinking 状态：
    - 表示当前 Router / Data Agent / Diagnose Agent 在执行的阶段，比如「正在识别意图」「正在查询物化视图」。
    - 前端可用一个“小脑袋转圈 / Loading Chips”来体现。
  - Artifacts（生成式 UI 指令）：
    - 由后端的 `render_ui_component` 工具返回，Data Agent 在 `data_agent_node` 中会把其解析为 JSON 并放进 `state["artifacts"]`。
    - 典型结构（示意）：
      ```json
      {
        "component_type": "LineChart",
        "title": "办公楼近7天用电趋势",
        "x_axis": [...],
        "series": [...],
        "meta": {
          "source_table": "daily_energy_summary",
          "building_id": "Office"
        }
      }
      ```
- **前端解析建议**
  - `stream_client.js` 负责：
    - 维护 SSE 连接、自动重连。
    - 根据 event 类型区分：
      - `type === "text"` → 追加到对话列表。
      - `type === "thinking"` → 更新状态条 / Loading。
      - `type === "artifact"` → 推入 `pinia` 中的 `chatStore.artifacts`。
  - 页面组件层：
    - `generative-ui/DynamicChart.vue` 根据 `component_type` 和 `series` 渲染 ECharts。
    - `generative-ui/WorkOrderCard.vue` 渲染工单卡片等交互控件。

#### 3. 数据 REST 接口（报表 / 面板预加载）

> 这些接口主要用于**非对话场景**的数据查询，比如仪表盘初始加载、下拉框可选项等。

- **典型用途**
  - Dashboard 页面打开时：
    - 调用「列出所有楼宇」接口：底层会用 `list_available_buildings`；
    - 调用「指定楼宇近 30 天每日能耗」接口：底层会用 `query_daily_energy_summary`（day 粒度，查物化视图）。
  - 对比分析页：
    - 调用「多楼同一指标对比」接口：底层用 `compare_metric_across_buildings`。
    - 调用「时间段同环比」接口：底层用 `compare_time_periods`。
- **前端调用方式建议**
  - 在 `frontend/src/api/` 下封装：
    - `getBuildings()`：GET `/api/data/buildings` → 返回所有可选楼宇（`building_type` + `meter_device_id` + `sqm`）。
    - `getDailySummary(params)`：GET `/api/data/daily-summary` → 包装 `building_id` / `date_range` / `granularity`。
    - 具体路由以实际 FastAPI `routes_data.py` 为准，可从 `/docs` 中查看。
