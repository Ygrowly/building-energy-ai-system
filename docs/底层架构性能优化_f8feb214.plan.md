# 底层架构性能优化（纯用户体验 + 输出质量导向）

## 当前完整调用链耗时分析

```
用户消息 → Router LLM (1-2s) → data_react ReAct (5-12s) → viz_engine (<0.1s) → Synthesis LLM (3-5s, 非流式干等) → 前端
```

diagnose 路径类似：Router (1-2s) → diagnose_agent ReAct (3-8s) → 最终回复也是一次性返回

---

## O1: 全链路流式输出 (体感影响最大)

**问题**:

- `_get_synthesis_llm()` 没有 `streaming=True` → Synthesis 3-5s 全部完成后才一次性返回文字
- `_get_diagnose_agent()` 的 ChatOpenAI 同样没有 `streaming=True` → 诊断回答也是干等

**改动**:

1. [data_agent.py](backend/app/graph/nodes/data_agent.py) L462: `_get_synthesis_llm()` 加 `streaming=True`
2. [diagnose_agent.py](backend/app/graph/nodes/diagnose_agent.py) L304, L320: 两个分支的 `ChatOpenAI` 都加 `streaming=True`

`routes_chat.py` 的 `on_chat_model_stream` 已有逻辑：对非 `data_react` 节点，捕获 token 就推 SSE。加 streaming 后自动生效，前端无需改动。

**效果**: 用户在工具调用完成后 ~0.3s 开始逐字看到文字，而不是干等 3-5s。两条路径都受益。

---

## O2: ReAct 硬性迭代上限

**问题**: `create_react_agent` 未设置 `recursion_limit`，仅靠 prompt 软约束。

**改动**:

1. [data_agent.py](backend/app/graph/nodes/data_agent.py) L384:
   `result = await agent.ainvoke(sub_state, config={"recursion_limit": 12})`
2. [diagnose_agent.py](backend/app/graph/nodes/diagnose_agent.py) L411:
   `result = await agent.ainvoke(sub_state, config={"recursion_limit": 15})`
   (diagnose 工具更多，给略高上限)

---

## O3: 消除 Fallback 双重调用

**问题**: 流式循环出异常时 `final_state_holder` 为空，触发 `graph.ainvoke()` 重试 — 延迟翻倍。

**改动**: [routes_chat.py](backend/app/api/routes_chat.py)

- 在每个 `on_chain_end` 节点成功时，增量合并 output 到 `final_state_holder`
- fallback 分支前加 `logger.warning`
- 已有部分结果时不做全图重试

---

## O4: Router 快速路径扩展

**问题**: `_try_fast_path` 仅覆盖问候语（<=30字符），高频业务查询仍走 LLM。

**改动**: [router_agent.py](backend/app/graph/nodes/router_agent.py)

将 `_try_fast_path` 扩展为"路由型"，新增返回 intent dict 的能力：

- `对比|查询|趋势|用电|用水|空调|能耗|COP` → `data_query`
- `建议|优化|改进|意见|诊断|异常|故障` → `fault_diagnosis`
- `工单|派单|报修|维修` → `work_order`
- `规范|标准|规定|手册|知识库` → `knowledge_query`

放宽 `_FAST_PATH_MAX_LEN` 到 80。

---

## O5: 按角色配置模型 (输出质量核心)

**问题**: 全局一个 `LLM_MODEL`，无法针对性优化各角色。

**改动**:

1. [config.py](backend/app/core/config.py) 新增：

```python
LLM_MODEL_ROUTER: str = ""
LLM_MODEL_REACT: str = ""
LLM_MODEL_SYNTHESIS: str = ""
LLM_MODEL_DIAGNOSE: str = ""
```

1. 各 agent 模块读取专属配置（为空时 fallback 到 `LLM_MODEL`）

**效果**: 可以用 flash 跑 Router/ReAct，用 plus/max 跑 Synthesis/Diagnose。`.env` 不配则全走 `LLM_MODEL`，零破坏性。

---

## O6: Router 结构化输出

**问题**: free-form JSON 解析不可靠，解析失败 fallback 到 clarify 伤体验。

**改动**: [router_agent.py](backend/app/graph/nodes/router_agent.py)

用 Pydantic model + `llm.with_structured_output(RouterDecision)` 替代 free-form JSON，保留 `_parse_router_output` 作为 fallback。

---

**改动**: [diagnose_agent.py](backend/app/graph/nodes/diagnose_agent.py) L281-284 修正变量名。
