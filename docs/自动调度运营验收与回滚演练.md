# 自动调度运营验收与回滚演练

## 1. 当前演练对象

本文用于 2026-04-11 之后的自动调度灰度运营验收，覆盖：

- 自动派工第二轮扩容：`Fox_public_Henry + high,medium + hvac`
- 自动重派第二轮扩展：`assigned -> overdue` 与 `accepted -> overdue`，其中 `accepted -> overdue` 要求已催办至少 1 次
- 大厅兜底：自动派工无法安全指定个人、或灰度外审批通过工单进入 `takeover_candidate`
- 自动调度运行健康：`scan_dispatch_sla` 最近扫描、慢扫描和触发量趋势
- 通用工单运营洞察：工单状态、SLA、人员、班组、楼宇热点

## 2. 当前关键配置

```env
ENABLE_AUTO_DISPATCH_EXECUTION=true
AUTO_DISPATCH_ALLOWED_BUILDINGS=Fox_public_Henry
AUTO_DISPATCH_ALLOWED_PRIORITIES=high,medium
AUTO_DISPATCH_ALLOWED_REQUIRED_SKILLS=hvac
ENABLE_AUTO_DISPATCH_FALLBACK_EXECUTION=true
AUTO_DISPATCH_FALLBACK_MIN_SCORE=95
AUTO_DISPATCH_FALLBACK_ALLOW_STANDBY=false
ENABLE_AUTO_DISPATCH_HALL_FALLBACK=true
AUTO_DISPATCH_CREATE_HALL_ON_ROLLOUT_SKIP=true

ENABLE_AUTO_REASSIGN_PHASE1_TRIGGER=true
ENABLE_AUTO_REASSIGN_EXECUTION=true
ENABLE_AUTO_REASSIGN_SHADOW_MODE=true
AUTO_REASSIGN_ALLOWED_BUILDINGS=Fox_public_Henry
AUTO_REASSIGN_ALLOWED_PRIORITIES=high
AUTO_REASSIGN_ALLOWED_REQUIRED_SKILLS=hvac
AUTO_REASSIGN_TRIGGER_ASSIGNED_OVERDUE=true
AUTO_REASSIGN_TRIGGER_ACCEPTED_OVERDUE=true
AUTO_REASSIGN_ACCEPTED_MIN_PREVIOUS_REMINDERS=1
AUTO_REASSIGN_TRIGGER_ASSIGNEE_UNAVAILABLE=false
```

## 3. 放量前检查

1. 重启后端 API，确保 `backend/.env` 重新加载。
2. 打开 Web：`派工中心 -> 派工洞察`。
3. 查看“通用运营洞察”，确认日期、楼宇、优先级、技能筛选能返回工单总数、SLA 风险、闭环率、平均完成耗时。
4. 查看“派工闭环观察”，确认自动派工灰度范围为 `Fox_public_Henry / high,medium / hvac`。
5. 查看“自动重派一期 / 影子观察”，确认：
   - 执行器开启
   - `accepted_overdue` 已进入触发原因
   - 责任人不可用未作为真执行口径
6. 查看“自动调度运行健康”，确认最近扫描成功，慢扫描没有集中出现。

## 4. 观察口径

每轮观察至少记录以下数据：

- 自动派工：直接派工量、低置信兜底量、大厅兜底量、灰度拦截量、复核需改派量
- 自动重派：触发量、真执行量、影子评估量、灰度阻断量、大厅兜底量
- 通用运营：待派工数、执行中数、待关闭数、已关闭数、超时数、待协同数、负载最高人员、热点楼宇
- 运行健康：扫描次数、失败次数、慢扫描次数、平均耗时、慢扫描时扫描量和重派触发量是否升高

## 5. 判停条件

命中任一条件应暂停继续扩容：

- 自动派工复核 `needs_reassign` 明显升高
- `medium + hvac` 自动派工集中进入大厅兜底，说明候选人覆盖不足
- `accepted -> overdue` 自动重派后出现明显误重派
- 大厅兜底长期打开无人接管
- 慢扫描集中出现，且伴随扫描量或自动重派触发量明显升高
- 审计日志缺失，无法追溯原责任人、新责任人、候选人分数或灰度阻断原因

## 6. 分级回滚

只回滚自动派工第二轮优先级扩容：

```env
AUTO_DISPATCH_ALLOWED_PRIORITIES=high
```

只回滚自动重派第二轮新增触发器：

```env
AUTO_REASSIGN_TRIGGER_ACCEPTED_OVERDUE=false
```

回到自动重派仅影子观察：

```env
ENABLE_AUTO_REASSIGN_EXECUTION=false
ENABLE_AUTO_REASSIGN_SHADOW_MODE=true
```

彻底暂停自动派工执行和大厅兜底：

```env
ENABLE_AUTO_DISPATCH_EXECUTION=false
ENABLE_AUTO_DISPATCH_FALLBACK_EXECUTION=false
ENABLE_AUTO_DISPATCH_HALL_FALLBACK=false
AUTO_DISPATCH_CREATE_HALL_ON_ROLLOUT_SKIP=false
AUTO_DISPATCH_ALLOW_LOW_CONFIDENCE_IN_GREY=false
AUTO_DISPATCH_ALLOW_HALL_FALLBACK_IN_GREY=false
```

回滚后必须重启后端 API，并重新查看“派工洞察”的配置和最近记录。

## 7. 误派处理流程

1. 在工单详情查看时间线和审计日志，确认是否为 `auto`、`auto_fallback` 或 `reassigned`。
2. 若责任人尚未接单，优先走正式改派。
3. 若已接单但未到场，确认是否已有催办；必要时改派并记录原因。
4. 若已到场或处理中，不自动改派，先由管理员判断是否走协同、升级或人工改派。
5. 在自动派工复核中标记 `needs_reassign`，并在备注里写清楚误派原因。
6. 回看“派工洞察”中对应楼宇、优先级、技能和人员分布，决定是否回滚灰度维度。

## 8. 慢扫描处理流程

1. 在“自动调度运行健康”里确认慢扫描样本的 `duration_ms`、扫描量、超时量和自动重派触发量。
2. 如果慢扫描伴随扫描量上升，先观察是否是业务量放大导致。
3. 如果慢扫描不伴随扫描量上升，优先检查候选人上下文准备、数据库查询和外部依赖。
4. 如果出现失败扫描，先暂停进一步扩容，再保留当前灰度范围观察一轮。
