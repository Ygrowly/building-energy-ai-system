### 第一部分：期望的核心功能、应用场景及其业务意义
在理想状态下，我希望这个系统能像一个拥有顶级专家经验的“数字能源管家”，它能自主看懂数据、能听懂人话、能指导一线工人干活。

#### 1. 核心功能一：基于大模型的“对话式”全域能耗洞察引擎
+ **应用场景**：集团管理层或物业经理无需在复杂的系统菜单里找报表，只需在对话框输入语音或文字：“_系统，调出上个月所有办公类建筑的用电和用水量，并告诉我哪栋楼的单位面积能耗（EUI）最高？_”系统瞬间吐出精准的数据、图表以及分析结论。
+ **解决的问题**：打破了传统“数据查询与报表生成效率低”的痛点。过去查个数据需要IT人员跑SQL或一层层点开仪表盘，现在实现了**零门槛的数据民主化**。
+ **业务意义**：极大提升决策响应速度。让业务人员不再被数据格式和系统操作困扰，直接获取结论，快速为制定“双碳”节能策略提供支撑。

#### 2. 核心功能二：数字孪生与动态能耗基线自校验
+ **应用场景**：系统在后台7×24小时运行。它不仅记录实际的供回水温度和能耗，还会根据当前的天气（室外温度、湿度）实时推算“在这个天气下，最优的供回水温度和预测能耗应该是多少”。一旦实际能耗与仿真期望值产生偏差，立刻无声息地进行记录并预警。
+ **解决的问题**：解决了传统建筑“隐性浪费”难以发现的问题（例如空调在凉爽的深夜依然满负荷运转）。
+ **业务意义**：从“事后看账单”转变为“事中动态调优”。为建筑制定动态的碳排放和能耗基线，实打实地降低20%以上的运行期碳排放。

#### 3. 核心功能三：专家级故障辅助诊断与运维工单闭环 (RAG智能运维助手)
+ **应用场景**：深夜，系统监测到某栋楼的暖通空调（HVAC）耗能突增且供回水温差异常。系统不仅自动生成一条 `anomaly_event`，还会直接推送给值班运维人员：“_发现设备能耗偏离基线30%，诊断原因为冷冻水泵节流异常。请带上X型号扳手前往地下二层机房，排查步骤如下：第一步...第二步..._”
+ **解决的问题**：极大地解决了“运维高度依赖人工经验、老员工离职导致知识断层、响应慢”的行业顽疾。
+ **业务意义**：将非标准化的老专家经验通过大模型转化为标准化的行动指南。缩短平均故障修复时间（MTTR），延长设备寿命，降低人工运维成本。

### 第二部分：期望的可视化效果与业务分析价值（紧扣数据库字段）
数据如果只是躺在表里，就是一堆无用的数字。我希望系统的前端大屏和Web界面能提供以下极具视觉冲击力且直指业务核心的可视化效果：

#### 1. 建筑级能效强度（EUI）多维气泡矩阵
+ **结合字段**：`buildings.building_id`, `buildings.primary_space_usage` (建筑用途), `buildings.sqm` (面积), `energy_data.electricity_kwh` (电耗), `energy_data.water_m3` (水耗)。
+ **可视化效果**：以气泡图展现。X轴为建筑面积（sqm），Y轴为单位面积能耗（kWh/sqm），气泡颜色代表不同建筑用途（如办公、医院、商业），气泡大小代表总碳排放/总能耗。
+ **分析场景与效果**：
    - **业务价值**：一眼看出哪类建筑是“电老虎”。如果我们发现某栋小面积的办公楼（气泡在左上方）单位能耗甚至高于同类型大面积建筑，说明该建筑的设备老化严重或管理极度粗放。
    - **结论**：指导集团下一财年的节能改造预算资金投向哪栋建筑收益最高。

#### 2. 暖通系统（HVAC）虚实映射与环境关联折线图
+ **结合字段**：`energy_data.timestamp`, `air_temp_c` (室外气温), `humidity_rh_pct` (湿度), `hac_energy` (暖通能耗), `sim_supply_temp_c` / `sim_return_temp_c` (仿真供回水温), 实际供回水温(可由业务推演)。
+ **可视化效果**：多轴双层折线图。底层用渐变色带表示室外温湿度（环境背景）；上层实线为实际暖通能耗（hac_energy），虚线为系统计算出的“仿真最优点”。同时附带供回水温差的阴影面积。
+ **分析场景与效果**：
    - **业务价值**：分析设备的运行效率是否与外界环境相匹配。比如，当室外气温（air_temp_c）已经降到20度，但 `hac_energy` 依旧居高不下，且实际供回水温与 `sim_supply_temp_c` 偏离过大。
    - **结论**：运维人员可以直观得出结论：“系统正在无效制冷/供热”。立刻对该时段的运行策略进行下发调整，这是最直接的节能手段。

#### 3. 24小时能耗日历热力图（Calendar Heatmap）
+ **结合字段**：`energy_data.timestamp`, `electricity_kwh`, `anomaly_status`。
+ **可视化效果**：类似GitHub提交记录的矩阵。纵轴为天（周一到周日），横轴为0-24小时。方块颜色从浅绿到深红代表能耗高低。当 `anomaly_status` 为异常时，该方块带上醒目的红色外边框或闪烁光标。
+ **分析场景与效果**：
    - **业务价值**：极其直观的“隐性浪费”抓手。通过看热力图的非工作时间段（如凌晨2点-5点，周末），如果发现本该全绿（低能耗）的方块出现橙色或红色。
    - **结论**：证明该建筑存在严重的下班未关停设备（如长明灯、未关空调）现象。通过这个图可以考核物业管理人员的夜间巡检执行力，立竿见影地杜绝管理漏洞。

#### 4. 异常根因溯源桑基图 (Sankey Diagram) 与健康度散点图
+ **结合字段**：`anomaly_events.rule_triggered` (触发规则), `hvac_root_cause` (根因), `deviation_pct` (偏离度), `is_resolved` (是否解决)。
+ **可视化效果**：左侧是各种触发规则（如“温差过大”、“能耗超标”），像河流一样汇聚到右侧的具体根因（如“过滤网堵塞”、“传感器失效”、“冷水机组故障”）。流带的宽度代表出现频率；同时在旁边配一个散点图，横轴时间，纵轴 `deviation_pct`（偏离度），红色未解决，绿色已解决。
+ **分析场景与效果**：
    - **业务价值**：让管理层从宏观角度俯视整个园区的设备健康状况。一眼看出过去一个月引发告警最多的“罪魁祸首”是什么设备部件。
    - **结论**：如果发现大量的“能耗超标”最终溯源都是“过滤网堵塞”或“某类传感器掉线”，那么我们将改变被动维修的策略，将这些部件列入“预测性维护”清单，批量提前采购并更换，将非计划停机时间降到最低。
