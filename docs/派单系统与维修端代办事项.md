- 自动派工灰度闸门已接入 AI 审批闭环：可通过 `AUTO_DISPATCH_ALLOWED_BUILDINGS / AUTO_DISPATCH_ALLOWED_PRIORITIES / AUTO_DISPATCH_ALLOWED_REQUIRED_SKILLS` 控制当前哪些工单允许直接进入自动派人；`AUTO_DISPATCH_ALLOW_LOW_CONFIDENCE_IN_GREY / AUTO_DISPATCH_ALLOW_HALL_FALLBACK_IN_GREY` 控制灰度范围内是否允许第二层、第三层策略。该闸门不影响管理员手动调用自动派工接口做验证。
- 当前本地灰度配置已调整为 `AUTO_DISPATCH_MIN_SCORE=105`，范围为 `Fox_public_Henry + high + hvac`；审批后闭环已允许保守低置信兜底和大厅兜底，其中 `AUTO_DISPATCH_CREATE_HALL_ON_ROLLOUT_SKIP=true` 会让灰度外审批通过工单进入大厅待调度；`GET /api/work-order-insights/metrics` 已返回 `auto_dispatch` 观测块，统计自动派工任务数、灰度拦截、尝试跳过和大厅兜底创建数。
- 自动重派只读建议已完成：`GET /api/work-orders/{ticket_id}/auto-reassign-evaluation`，会排除当前责任人，并检查超时、派工阶段、尝试次数、候选人得分/分差/负载。

### 仍待后续阶段处理

- 自动派工灰度扩容策略：当前第一批正式灰度策略已经固化，后续只需决定是否把更多楼宇、优先级或技能纳入“直接自动派人”范围。
- 自动重派正式运营：执行器已具备，但是否打开 `ENABLE_AUTO_REASSIGN_EXECUTION` 仍需等自动派工复核与 SLA 运营数据稳定后决定。
- 运营洞察通用参数化查询与 LLM 表达层。
