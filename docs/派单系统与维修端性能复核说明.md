**目标**
本轮复核聚焦派单系统当前最常走的查询路径，优先处理“列表查询 + 排序 + 当前态过滤”这类容易随着数据量增长而变慢的场景。

**复核范围**
- `incident` 列表
- `batch dispatch preview`
- `dispatch task` 列表与 SLA 扫描
- `工单大厅` 列表
- `工单大厅申请` 加载

**确认过的高频查询**
1. `incident` 列表  
位置：[incident_service.py](e:/27_fwwb_A08/project/backend/app/services/incident_service.py#L674)  
特征：按 `current_assigned_to / workflow_status / building_id` 过滤，并按 `last_seen_at desc, created_at desc` 排序。

2. `batch dispatch preview`  
位置：[work_order_service.py](e:/27_fwwb_A08/project/backend/app/services/work_order_service.py#L981)  
特征：按 `status=pending_dispatch` 为主扫描，附带 `building_id / priority` 过滤，按 `pending_dispatch_at / created_at` 排序。

3. `dispatch task` 列表  
位置：[dispatch_service.py](e:/27_fwwb_A08/project/backend/app/services/dispatch_service.py#L300)  
特征：按 `assigned_to / dispatch_status / is_current` 过滤，并按 `assigned_at desc, attempt_no desc` 排序。

4. SLA 扫描  
位置：[dispatch_service.py](e:/27_fwwb_A08/project/backend/app/services/dispatch_service.py#L354)  
特征：按 `is_current=true + dispatch_status in (...)` 扫描活跃派工，并按 `assigned_at asc` 顺序处理。

5. 工单大厅列表  
位置：[dispatch_hall_service.py](e:/27_fwwb_A08/project/backend/app/services/dispatch_hall_service.py#L360)  
特征：按 `status / entry_type / assigned_to` 等过滤，并按 `created_at desc, id desc` 排序。

6. 工单大厅申请加载  
位置：[dispatch_hall_service.py](e:/27_fwwb_A08/project/backend/app/services/dispatch_hall_service.py#L410)  
特征：按 `hall_entry_id in (...)` 查询，并按 `created_at asc` 组装申请时间线。
