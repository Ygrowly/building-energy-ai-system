# 自动重派第二批灰度验收清单

## 1. 目的

本文用于验收 2026-04-11 第二批自动重派正式运营扩展。本轮只新增一个真执行触发器：`accepted -> overdue`，并要求此前至少已有 1 次催办；其他触发器和灰度范围继续保持保守。

## 2. 当前灰度配置

```env
ENABLE_AUTO_REASSIGN_PHASE1_TRIGGER=true
ENABLE_AUTO_REASSIGN_EXECUTION=true
ENABLE_AUTO_REASSIGN_SHADOW_MODE=true

AUTO_REASSIGN_ALLOWED_BUILDINGS=Fox_public_Henry
AUTO_REASSIGN_ALLOWED_PRIORITIES=high
AUTO_REASSIGN_ALLOWED_REQUIRED_SKILLS=hvac

AUTO_REASSIGN_TRIGGER_ASSIGNED_OVERDUE=true
AUTO_REASSIGN_TRIGGER_ACCEPTED_OVERDUE=true
AUTO_REASSIGN_ACCEPTED_MIN_PREVIOUS_REMINDERS=1
AUTO_REASSIGN_TRIGGER_ASSIGNEE_UNAVAILABLE=false

AUTO_REASSIGN_MIN_SCORE=115
AUTO_REASSIGN_MIN_GAP=10
AUTO_REASSIGN_REQUIRE_ON_DUTY=true
AUTO_REASSIGN_REQUIRE_OVERDUE=true
AUTO_REASSIGN_MAX_ATTEMPT_NO=3
```

## 3. 验收样本

建议准备 4 类样本：

1. A 单：`assigned -> overdue` 灰度内，验证第一批能力仍正常。
2. B 单：`accepted -> overdue` 灰度内，且 `reminder_count >= 1`，验证第二批新增触发器会自动重派。
3. C 单：`accepted -> overdue` 灰度内，但 `reminder_count = 0`，验证未催办过不会直接自动重派。
4. D 单：当前责任人客观不可用，但 `AUTO_REASSIGN_TRIGGER_ASSIGNEE_UNAVAILABLE=false`，验证不会误真执行。

## 4. 关键步骤

1. 记录每张样本单的 `ticket_id`、楼宇、优先级、技能、当前责任人、当前派工状态和 `reminder_count`。
2. 让样本进入对应超时或责任人不可用状态。
3. 手工触发 `POST /api/admin/scan-dispatch-sla`。
4. 刷新工单详情、时间线和“派工洞察 -> 自动重派一期 / 影子观察”。
5. 对 B 单额外确认旧派工变为 `transferred`，新派工成为 `is_current=true`。

## 5. 通过标准

- A 单继续可以自动重派。
- B 单在 `reminder_count >= 1` 后可以自动重派。
- C 单不会因为刚进入 `accepted -> overdue` 就立即自动重派。
- D 单不会因为责任人不可用触发器关闭而被自动改派。
- SLA 扫描返回能看到新增触发量，且审计记录包含 `auto_reassign_shadow_evaluated`；真执行样本还应包含 `auto_reassign_executed`。

## 6. 回滚口径

如果 B 单出现误重派，先回退第二批新增触发器：

```env
AUTO_REASSIGN_TRIGGER_ACCEPTED_OVERDUE=false
```

如果自动重派整体异常，再退回仅影子观察：

```env
ENABLE_AUTO_REASSIGN_EXECUTION=false
ENABLE_AUTO_REASSIGN_SHADOW_MODE=true
```
