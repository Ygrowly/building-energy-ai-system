# 04 用户使用手册

> 面向系统管理员、运维经理、维修人员和演示答辩场景编写。
> 本手册重点说明系统安装部署步骤、各端模块操作流程以及常见问题排查方法。

## 1. 系统简介

### 1.1 系统定位

“绿枢智控”是一套面向建筑能源场景的智能管理系统，围绕数据治理、查询统计、智慧运维和移动维修闭环展开。系统将建筑能耗数据、异常检测、预测预警、工单审批、派工执行、维修指导与经验沉淀整合在同一平台中，支持 Web 管理端、移动运维端、移动维修端以及 AI 助手协同工作。

### 1.2 用户角色

| 角色 | 主要职责 |
| --- | --- |
| 系统管理员 `admin` | 维护系统配置、管理账号、查看全局数据、监督工单流程 |
| 运维经理 `manager` | 查看总览、审阅工单、派工/改派、执行跟踪、运营问询 |
| 维修人员 `ops` | 接单、到场、开始处理、协同维修、反馈结果、沉淀经验 |

> 说明：系统注册接口可创建新账号，但新账号默认不是完整演示角色。正式演示前建议预先准备带角色的演示账号。

### 1.3 终端入口说明

| 终端 | 说明 | 典型访问方式 |
| --- | --- | --- |
| Web 管理端 | 首页总览、数据中心、查询统计、智慧运维、工单中心、人员画像 | `http://localhost:5173` |
| 移动运维端 | 总览查看、工单审阅、派工/改派、执行跟踪 | Uni-app H5，通常为 `http://localhost:5174` |
| 移动维修端 | 工单大厅、我的工单、工单详情、维小修 | Uni-app H5，通常为 `http://localhost:5174` |
| 运小维 | 运维管理端只读问询助手 | 独立 AI 对话入口或相关管理端接入点 |
| 维小修 | 维修执行与现场指导助手 | 移动维修端“维小修”页面 |

## 2. 安装与部署步骤

### 2.1 环境准备

建议准备以下运行环境：

| 组件 | 建议版本 | 说明 |
| --- | --- | --- |
| Python | 3.10+ | 运行 FastAPI 后端 |
| Node.js | 18+ | 运行前端与 Uni-app |
| pnpm | 8+ | 安装前端与移动端依赖 |
| PostgreSQL | 14/15 | 业务主数据库 |
| Redis | 7+ | 缓存与高频接口加速 |
| RAGFlow | 与本地部署版本一致 | 知识库文档解析与检索 |

项目目录结构如下：

- `backend/`：FastAPI 后端、模型、服务、测试
- `frontend/`：Vue 3 Web 管理端
- `mobile/`：Uni-app 移动端
- `docs/`：赛题与交付文档

### 2.2 后端部署

#### 步骤 1：安装依赖

```powershell
cd backend
pip install -r requirements.txt
```

#### 步骤 2：配置环境变量

将 `backend/.env.example` 复制为 `backend/.env`，按实际环境修改以下关键项：

- `DATABASE_URL`、`SYNC_DATABASE_URL`
- `REDIS_URL`
- `LLM_API_KEY` 或 `DASHSCOPE_API_KEY`
- `RAGFLOW_API_URL`、`RAGFLOW_API_KEY`、`RAGFLOW_DATASET_ID`
- `DATA_TIME_START`、`DATA_TIME_END`

#### 步骤 3：启动 Redis

仓库根目录下执行：

```powershell
docker compose up -d
```

> 注意：当前 `docker-compose.yml` 仅负责启动本地 Redis，PostgreSQL 与 RAGFlow 需要单独准备。

#### 步骤 4：启动后端服务

```powershell
cd backend
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

#### 步骤 5：健康检查

启动完成后，访问以下接口验证服务状态：

- `GET http://127.0.0.1:8000/health`
- `GET http://127.0.0.1:8000/health/db`

若两个接口均返回正常状态，说明后端已具备基本运行条件。

### 2.3 前端部署

```powershell
cd frontend
pnpm install
pnpm dev
```

默认情况下，Web 管理端运行在 `http://localhost:5173`。

如需构建产物，可执行：

```powershell
pnpm build
```

### 2.4 移动端 H5 启动

```powershell
cd mobile
pnpm install
pnpm dev:h5
```

Uni-app H5 默认会在本地启动调试地址，常见为 `http://localhost:5174`。若实际端口不同，以终端输出为准。

### 2.5 数据库、Redis、RAGFlow 配置说明

#### PostgreSQL

- 用于存储建筑、设备、能耗数据、异常事件、预测事件、工单、派工和经验数据。
- 必须保证 `DATABASE_URL` 与 `SYNC_DATABASE_URL` 可连通。

#### Redis

- 默认连接：`redis://localhost:6379/0`
- 用于首页总览、工单、异常与部分对话结果缓存。

#### RAGFlow

- 默认地址：`http://localhost:9380`
- 用于上传运维手册、设备文档和规程文件，并完成解析与向量化。
- 若未配置，知识库上传、解析和部分 AI 问答能力会降级或不可用。

### 2.6 登录验证

部署完成后建议按以下顺序验证：

1. 打开 Web 登录页，确认可访问。
2. 使用预置演示账号登录管理端。
3. 打开移动端 H5，分别以运维角色和维修角色登录。
4. 检查首页总览、工单列表、数据中心是否能正常加载。

## 3. Web 管理端操作流程

### 3.1 首页总览

用途：查看系统整体运行状态、建筑概况和异常态势。

操作步骤：

1. 登录 Web 管理端后进入首页。
2. 通过顶部建筑切换器选择“总览 / 教学楼 / 办公楼 / 公共服务类建筑”。
3. 查看 KPI 卡片、能耗概况、近 7 天异常、预测预警和 AI 洞察摘要。
4. 如需更新数据，刷新页面或触发相关刷新按钮。

建议用途：

- 答辩演示时作为系统总入口。
- 快速查看当前建筑能耗、异常集中度与 AI 建议。

### 3.2 数据中心

用途：上传结构化数据集、分析字段、导入 `energy_data`、上传知识文档。

#### 数据集上传与导入

操作步骤：

1. 进入“数据中心”页面。
2. 在“数据集”页签上传 CSV/Excel 文件。
3. 查看系统自动解析的列信息、统计信息和样本行。
4. 点击“导入到 `energy_data`”，等待导入进度完成。
5. 导入完成后，可在页面下方查看已导入的 `energy_data` 记录并进行增删改查。

适用场景：

- 导入标准化能耗数据集。
- 验证字段映射和数据质量。

#### 知识库文档上传与解析

操作步骤：

1. 切换到“知识库”页签。
2. 上传 PDF、Word 或 TXT 文档。
3. 点击解析按钮，等待 RAGFlow 完成切片与向量化。
4. 解析成功后，该文档可被运小维和维小修检索使用。

适用场景：

- 上传运维手册、设备说明书、维修规范。

### 3.3 查询统计

用途：进行条件筛选查询、统计分析、图表查看和报表导出。

操作步骤：

1. 进入“查询统计”页面。
2. 选择建筑、开始日期、结束日期。
3. 勾选需要查看的监测参数，如电耗、水耗、空调能耗、环境温度等。
4. 点击“查询”。
5. 在“统计分析”视图中查看 KPI 卡片、能耗图、COP 图、环境图和设备图。
6. 在“数据展示”视图中查看表格明细。
7. 如需导出统计结果，通过报表导出入口导出数据。

适用场景：

- 展示时段汇总
- 进行 COP 计算与趋势分析
- 对比不同建筑运行状态

### 3.4 智慧运维

用途：查看近期异常、预测预警、AI 诊断建议和可解释性依据。

操作步骤：

1. 进入“智慧运维”页面。
2. 查看近期异常记录和预测预警列表。
3. 通过筛选时间窗口查看不同范围的数据。
4. 在 AI 控制台输入异常场景或运维问题，触发智能诊断。
5. 查看 AI 返回的结论、数据证据、知识依据和工单草稿。

典型问题示例：

- “办公楼凌晨 3 点能耗是不是有异常？”
- “最近 7 天哪类异常最多？”
- “这张工单为什么被 AI 建议派修？”

### 3.5 工单中心

用途：完成工单审阅、待派工管理、派工执行与执行跟踪。

系统将工单中心分为四个主要视图：

- 总览
- 工单审阅
- 派工中心
- 执行跟踪

#### 工单审阅

1. 进入工单中心后切换到“工单审阅”。
2. 查看待 AI 审阅、AI 已驳回或待人工覆盖的工单。
3. 查看工单详情、AI 理由和上下文信息。
4. 根据需要执行批准、驳回或人工覆盖。

#### 派工中心

1. 切换到“派工中心”。
2. 查看待派工工单、推荐候选人和派工理由。
3. 选择维修人员，执行派工。
4. 如需要，可执行改派或查看自动派工复核结果。

#### 执行跟踪

1. 切换到“执行跟踪”。
2. 查看已派工、待接单、超时、待协同等工单状态。
3. 跟踪维修执行过程，必要时进行催办或调整。

### 3.6 人员画像

用途：维护维修人员班组、技能、可派工状态与容量上限，为派工推荐提供基础数据。

操作步骤：

1. 进入“班组与人员画像”页面。
2. 选择某位维修人员。
3. 设置班组、值班状态、是否允许参与派工、最大在手工单数、技能标签等信息。
4. 保存画像。

适用场景：

- 优化派工推荐质量
- 支撑后续自动派工与自动重派能力

### 3.7 通知中心

用途：查看未读消息、工单通知、协同提醒和派工状态更新。

操作步骤：

1. 点击页面右上角消息入口。
2. 查看未读通知摘要。
3. 按分类查看派工、超时、协同等通知。
4. 批量标记已读或全部已读。

## 4. 移动运维端操作流程

### 4.1 登录

1. 打开移动端 H5 页面。
2. 使用运维经理或管理员账号登录。
3. 登录成功后，系统进入运维侧首页。

### 4.2 总览查看

运维端首页主要用于查看：

- 建筑能耗总览
- 当前异常状态
- 待处理工单
- 重点风险建筑

建议操作：

1. 切换建筑范围。
2. 查看异常建筑与待处理工单。
3. 进入工单页继续处理。

### 4.3 工单审阅

1. 打开“工单审阅”页。
2. 切换“待派工 / AI 已驳回 / 已派单 / 工单大厅”等标签。
3. 点击具体工单，查看异常摘要、AI 理由和推荐处理方式。
4. 根据实际情况执行审批、覆盖或关闭操作。

### 4.4 派工与改派

1. 对待派工工单点击“立即派工”。
2. 查看候选维修人员、班组、推荐分和推荐理由。
3. 选择维修人员完成派工。
4. 如当前责任人不合适，可通过改派入口重新分配。
5. 对高置信工单可使用批量派工建议。

### 4.5 执行跟踪

1. 查看当前工单处于待接单、已接单、到场、处理中、待协同或超时状态。
2. 对超时工单进行催办、改派或升级处理。
3. 对共享工单大厅中的协同/接管申请进行处理。

### 4.6 运小维问询

运小维用于只读问询，不直接修改业务状态。

推荐用法：

- 查询工单当前状态
- 查询某类异常近期分布
- 查询某段时间内谁处理工单最多
- 解释为什么出现超时、协同或改派

使用说明：

1. 打开独立 AI 对话页或相关入口。
2. 输入问题。
3. 查看返回的结论、事实摘要和证据引用。

## 5. 移动维修端操作流程

### 5.1 登录

1. 打开移动端 H5 页面。
2. 使用维修人员账号登录。
3. 登录后进入维修工作台。

### 5.2 工单大厅与我的工单

维修侧常用入口包括：

- 工单大厅：查看可协同或可接管任务
- 我的工单：查看已正式分配到个人的工单
- 消息中心：查看提醒、通知和超时工单

建议操作：

1. 在工作台先查看今日工单数量与逾期工单。
2. 从“我的工单”进入具体任务处理。
3. 需要协同时，关注工单大厅中的共享任务。

### 5.3 接单、到场、开始处理

工单执行的标准流程如下：

1. 接单：确认接受派工任务。
2. 到场：到达现场后确认到场。
3. 开始处理：正式进入维修处理阶段。

操作路径：

1. 打开工单详情。
2. 根据当前状态点击对应动作按钮。
3. 系统记录时间节点并更新执行状态。

### 5.4 协同处理

当工单需要跨班组或多人协同时：

1. 在工单详情中发起协同请求。
2. 运维端审核后指派协同人员。
3. 协同人员接单并参与处理。
4. 协同解决后更新工单状态。

### 5.5 进入维小修

维小修仅在工单进入可指导阶段后开放，通常要求工单已进入如下状态之一：

- `processing`
- `waiting_support`
- `supporting`

操作步骤：

1. 从“我的工单”或工单详情进入“维小修”页面。
2. 查看系统生成的工单摘要和步骤卡片。
3. 通过文字、语音或图片与维小修交互。
4. 根据建议完成步骤推进。

维小修可提供：

- 维修步骤建议
- 现场图片分析
- 语音转文字
- 回复播报
- 协同建议和经验引用

### 5.6 提交维修反馈与经验

工单处理完成后：

1. 在工单详情中提交处理结果。
2. 填写维修备注、故障原因和处理过程。
3. 若有可复用经验，可补充经验描述。
4. 系统将经验沉淀到经验库，用于后续维小修推荐。

## 6. AI 助手使用说明

### 6.1 运小维使用方式

定位：面向管理端的只读问询助手。

适用问题：

- “本周哪栋楼异常最多？”
- “这张工单为什么超时？”
- “谁接单最多，谁到场最慢？”

特点：

- 以事实查询和解释为主
- 不直接修改工单状态
- 可返回证据和过程说明

### 6.2 维小修使用方式

定位：面向维修端的执行型助手。

适用场景：

- 工单已经开始处理，需要现场指导
- 需要查看维修步骤、注意事项或案例经验
- 需要结合现场图片进行故障辅助判断

特点：

- 提供步骤卡片
- 支持语音/图片/文本混合输入
- 支持维修经验复用

### 6.3 AI 与人工确认边界

系统采用“AI 建议 + 人工确认”的协同方式：

- AI 可生成分析结论、审批建议、派工建议和维修指导。
- 关键业务动作仍由系统状态机和人工操作共同确认。
- 运小维默认不执行写操作。
- 维小修涉及工单状态动作时，仍需通过后端动作校验。

## 7. 常见问题排查

| 问题现象 | 可能原因 | 排查方法 |
| --- | --- | --- |
| 后端启动失败 | `.env` 未配置、数据库不可达、端口被占用 | 检查 `backend/.env`、访问 `/health/db`、确认 8000 端口未冲突 |
| Web 或移动端无法加载数据 | 后端未启动、跨域配置不匹配、Token 失效 | 确认后端运行在 8000，重新登录，查看浏览器控制台网络请求 |
| 数据导入失败 | 时间字段或建筑字段不符合要求，必需字段缺失 | 在数据中心先查看列信息，确认存在标准化字段，再重新导入 |
| 查询结果为空 | 时间范围不在系统数据窗口内，或所选建筑无数据 | 检查 `DATA_TIME_START/DATA_TIME_END`，优先使用系统已有时间范围 |
| 知识库上传/解析失败 | `RAGFLOW_API_KEY` 或 `RAGFLOW_DATASET_ID` 未配置，RAGFlow 服务未启动 | 检查 RAGFlow 地址与密钥，确认 `http://localhost:9380` 可访问 |
| 工单无法派发 | 人员画像不完整、无可派工人员、工单不在待派工状态 | 检查维修人员班组/技能/值班状态，确认工单状态为 `pending_dispatch` |
| 维修端看不到工单 | 当前账号不是 `ops` 角色，或工单未真正派到该人员 | 检查账号角色，确认已完成派工且 `assigned_to` 正确 |
| 维小修无法进入 | 工单尚未进入可指导状态 | 先完成接单、到场、开始处理，再进入维小修 |
| AI 助手不可用或降级 | 模型 API Key 未配置、知识库未配置、外部服务不可用 | 检查 `LLM_API_KEY` / `DASHSCOPE_API_KEY` / `AI_*` 与 RAGFlow 配置 |

### 8.4 演示建议流程

推荐答辩演示顺序如下：

1. 进入 Web 首页总览，展示整体建筑能耗与异常态势。

3. 进入查询统计页，展示条件查询、COP 分析与报表导出。

5. 进入工单中心，展示 AI 审批、派工和执行跟踪。
6. 切换到移动维修端，展示接单、到场、开始处理、维小修指导与维修反馈。
