# 自动派工灰度正式运营策略

## 当前灰度口径

本轮正式灰度采用“AI 审批通过后不静默滞留”的闭环口径：

- 灰度范围内优先高置信自动派给具体维修人员。
- 高置信不满足时，允许低置信兜底，但阈值收紧到 `95`，且只允许值班人员。
- 无法指定具体人员时，允许进入工单大厅兜底。
- 灰度范围外不直接自动派人，但允许进入工单大厅待调度，避免审批通过后长期停在待派工。

```env
ENABLE_AUTO_DISPATCH_EXECUTION=true
AUTO_DISPATCH_MIN_SCORE=105
AUTO_DISPATCH_MIN_GAP=10
AUTO_DISPATCH_REQUIRE_ON_DUTY=true
AUTO_DISPATCH_ALLOWED_BUILDINGS=Fox_public_Henry
AUTO_DISPATCH_ALLOWED_PRIORITIES=high
AUTO_DISPATCH_ALLOWED_REQUIRED_SKILLS=hvac
ENABLE_AUTO_DISPATCH_FALLBACK_EXECUTION=true
AUTO_DISPATCH_FALLBACK_MIN_SCORE=95
AUTO_DISPATCH_FALLBACK_ALLOW_STANDBY=false
ENABLE_AUTO_DISPATCH_HALL_FALLBACK=true
AUTO_DISPATCH_CREATE_HALL_ON_ROLLOUT_SKIP=true
AUTO_DISPATCH_ALLOW_LOW_CONFIDENCE_IN_GREY=true
AUTO_DISPATCH_ALLOW_HALL_FALLBACK_IN_GREY=true
```

含义：

- 只处理 `Fox_public_Henry` 楼宇。
- 只处理 `high` 优先级工单。
- 只处理派工需求包含 `hvac` 技能的工单。
- 第一候选人推荐分至少 `105`，与第二候选人的分差至少 `10`。
- 第一候选人必须值班中。
- 低置信兜底只允许值班人员，且推荐分至少 `95`。
- 大厅兜底作为“无法安全指定个人”的最后闭环，不直接改变具体负责人。
- 灰度外审批通过工单不会直接自动派人，只会进入大厅待调度。
- 自动重派执行器继续默认关闭，不纳入本轮灰度。

## 执行步骤

1. 确认 `backend/.env` 按当前灰度口径配置。
2. 重启后端 API，使 `backend/.env` 重新加载。
3. 触发或等待 AI 审批通过后的工单闭环。
4. 用 `GET /api/work-order-insights/metrics` 查看 `auto_dispatch` 观测块，确认：
   - `enabled=true`
   - `rules.min_score=105`
   - `rollout.allowed_buildings=["Fox_public_Henry"]`
   - `rollout.allowed_priorities=["high"]`
   - `rollout.allowed_required_skills=["hvac"]`
   - `allow_low_confidence=true`
   - `allow_hall_fallback=true`
   - `rules.fallback_min_score=95`
   - `rules.fallback_allow_standby=false`
   - `rules.create_hall_on_rollout_skip=true`
5. 用 Web 端“工单审阅 / 自动派工复核”页签抽查自动派工单，管理员标记“已复核”或“需改派”。
6. 用工单大厅查看自动兜底入口，重点关注 `reason=auto_dispatch_rollout_hall_fallback_created` 和 `strategy=rollout_hall_fallback` 的审计记录。

## 回滚步骤

最小回滚只需要关闭执行总开关：

```env
ENABLE_AUTO_DISPATCH_EXECUTION=false
```

如果需要彻底回到观察模式，同时保持灰度条件可见，可保留白名单和值班/阈值配置不变。系统会继续记录 AI 审批后的自动派工尝试跳过原因，但不会写入新的自动派工任务。

更保守的回滚配置：

```env
ENABLE_AUTO_DISPATCH_EXECUTION=false
ENABLE_AUTO_DISPATCH_FALLBACK_EXECUTION=false
ENABLE_AUTO_DISPATCH_HALL_FALLBACK=false
AUTO_DISPATCH_CREATE_HALL_ON_ROLLOUT_SKIP=false
AUTO_DISPATCH_ALLOW_LOW_CONFIDENCE_IN_GREY=false
AUTO_DISPATCH_ALLOW_HALL_FALLBACK_IN_GREY=false
ENABLE_AUTO_REASSIGN_EXECUTION=false
```

回滚后应重启后端，并再次查看 `GET /api/work-order-insights/metrics`，确认 `auto_dispatch.enabled=false` 且后续没有新增 `dispatch_mode=auto` 的当前派工任务。

## 扩容条件

只有满足以下条件后才进入下一轮扩容：

- 自动派工复核队列连续观察期内没有明显误派。
- 需改派比例稳定在运营可接受范围内。
- SLA 催办和自动重派仍保持默认关闭或人工可控。
- 自动派工复核和工单大厅里没有出现集中误派、重复接管或无人响应。
- 回滚流程已经在测试环境演练通过。

下一轮扩容建议一次只放开一个维度，例如先增加楼宇，再增加优先级或技能，不要同时放开多个维度。
